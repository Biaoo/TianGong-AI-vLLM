# H3 NVFP4 音视频服务

已通过 GPUStack 专用鉴权路由的单卡 SM120 真实生成验收：480P、768P 各一段约 5 秒视频，均包含双声道音频。默认使用 36 层质量解码器、八步采样、逐层内存卸载和单请求并发。当前验收不覆盖长视频、持续压力、多参考输入或高并发。

## 模型组成

选用 [FastVideo/FastH3-Omni-NVFP4-QAD](https://huggingface.co/FastVideo/FastH3-Omni-NVFP4-QAD)，是 MiniMax H3 的八步蒸馏、量化感知训练派生版本，不是原版 BF16 的等价精度替换。此配置为 Ref2VA：至少提供一张图像或一段视频参考，输出同步音视频；不能将它描述为无参考的纯文生视频服务。

一条完整流水线包括扩散模型、Qwen3-VL 文本/视觉编码器、视频 VAE、音频 VAE，作为一个 GPUStack 服务管理。扩散与编码器使用模型发布者的 NVFP4 版本；保留原版 VAE 所需权重，并默认使用 36 层 NVFP4 视频解码器。8 层快速解码器已下载但未启用，尚未完成与默认解码器的实测对比。

[release.json](../deploy/h3/release.json) 固定模型与源码版本。[主模型清单](../deploy/h3/model-manifest.json) 排除重复的 `transformer/`，保留 `transformer_ref/`，共 64.18 GiB。固定 vLLM-Omni 源码还会加载原版 H3 的 `Ref2VA/video_vae/` 和 `Ref2VA/audio_vae/`；[VAE 清单](../deploy/h3/vae-manifest.json) 为 10.26 GiB。总下载约 74.44 GiB，不能把磁盘文件大小当作推理峰值显存。

## 下载与验证

`scripts/download_hf_snapshot.py` 使用完整 revision、文件大小和 SHA256；小型非 LFS 文件先核对原始 Git blob SHA1，再记录 SHA256。下载锁防止并发写同一快照，curl 保留 `.part`，校验通过后才替换最终文件。`--verify-only` 不联网、不写模型目录。`--transport hub` 仅供已经安装固定 Hugging Face Hub/Xet 的隔离下载容器使用，不添加宿主 ML 依赖。

ModelScope 镜像已比对：19 个大型权重的大小与 SHA256 一致。主模型镜像是 `FastVideo/FastH3-Omni-NVFP4-QAD`，原版镜像命名空间为 `MiniMax/MiniMax-H3`。两边 Git 提交不同，镜像提交见 release.json；下载仍按原 HF 清单逐文件验证。`.gitattributes` 是仓库特有文件，继续使用原 HF 内容。任何配置或代码文件散列不一致都会中止，不混用发布版本。

在新建专用模型父目录下，用完整 HF revision 命名主模型目录；原版 VAE 放在同一父目录的 `hub/models--MiniMaxAI--MiniMax-H3/snapshots/<base-revision>/`。将对应清单复制成各自的 `snapshot-manifest.json`，然后执行：

```bash
python3 scripts/download_hf_snapshot.py \
  --model FastVideo/FastH3-Omni-NVFP4-QAD \
  --revision f01e6a23ac6066aa9eb622cf94b6259442e70ec2 \
  --directory /srv/models/h3/f01e6a23ac6066aa9eb622cf94b6259442e70ec2 \
  --exclude-prefix transformer/ --transport modelscope --workers 6 \
  --mirror-model FastVideo/FastH3-Omni-NVFP4-QAD \
  --mirror-revision aed5d1f3da2d064a22f19e9d97377473813b9425

python3 scripts/download_hf_snapshot.py \
  --model MiniMaxAI/MiniMax-H3 \
  --revision 9bfb6693f2cf6de171db46d1aa586f67d773a1da \
  --directory /srv/models/h3/hub/models--MiniMaxAI--MiniMax-H3/snapshots/9bfb6693f2cf6de171db46d1aa586f67d773a1da \
  --include-prefix Ref2VA/video_vae/ --include-prefix Ref2VA/audio_vae/ \
  --transport modelscope --workers 6 --mirror-model MiniMax/MiniMax-H3 \
  --mirror-revision 57559a6720ddaa2eaee52b09ec2ef011127997b2
```

## 构建与运行验收

[Dockerfile](../deploy/h3/Dockerfile) 基于固定摘要的官方 vLLM-Omni CUDA 13 镜像，保留 FlashInfer 0.7.0.post1 的 cubin、JIT shim 和全部架构 provider，再安装固定提交的 Omni 源码。只装 SM120 provider 不足以满足此版本的 shim 依赖。基础镜像的 NCCL override 与 Torch 元数据冲突，派生镜像固定为 Torch 要求的 2.29.7；同时移除无依赖方的遗留 `opentelemetry-exporter-otlp-common`，保留相互兼容的 OTel 1.40 组件。

[runtime-constraints.txt](../deploy/h3/runtime-constraints.txt) 固定实际运行依赖；构建必须通过 `uv pip check`，启动时不安装或升级包。构建脚本从给定源码仓库提取固定提交，并拒绝覆盖已存在的镜像标签：

```bash
bash deploy/h3/build.sh /path/to/vllm-omni-checkout
```

包索引默认使用阿里云 PyPI 镜像；遇到本地 DNS/IPv6 故障可通过 `H3_PACKAGE_IPV4` 为本次构建指定已核实的镜像 IPv4，不修改宿主 DNS 或 Docker 全局配置。模型下载的 `--ipv4` 同样只影响该次 curl 下载。

SM120 的独立 NVFP4 量化与矩阵乘法已在真实 GPU 上通过有限值、形状和数值误差检查；这只证明算子可执行，不能代替视频模型的端到端验收。

- 固定 vLLM-Omni 源码的单卡 Blackwell recipe 采用 layer offload、FASTVIDEO_VSA、八步、guidance 1；[quality.yaml](../deploy/h3/quality.yaml) 在此基础上限制运行并发为 1。
- [serve.py](../deploy/h3/serve.py) 校验两套快照后离线启动，可选只读模型 bind mount和快速解码器。模型自带 VAE Python 代码属于被固定并核验的 trust-remote-code 依赖。vLLM 0.32 默认关闭请求正文日志；不要传旧 `--disable-log-requests`，也不要向 Omni diffusion 显式传 `enable_log_requests`，该字段不属于扩散引擎配置。
- [h3_runtime.py](../deploy/h3/h3_runtime.py) 的 worker extension 将 PyTorch allocator 默认限制为可见显存的 35%。这不是所有 CUDA 分配的硬隔离，需要实际测峰值，并核对同卡服务预算。IP middleware 只接受显式网关、worker、回环地址，不信任 X-Forwarded-For。
- 使用固定派生镜像创建 GPUStack custom backend，首次保持副本为 0，检查后再启动。模型固定到指定 worker/GPU；`GPUSTACK_MODEL_VRAM_CLAIM` 按字节设置显存调度预算，与 PyTorch fraction 分别配置。GPUStack custom backend 的 RAM 估算不代表卸载需要的实际内存，启动前必须检查主机可用内存。不加入原生部署器的 `all`。
- GPUStack worker 增加 H3 专用父目录挂载时保留原 overlay；上线前后核验原容器 ID、启动时间与真实请求。不得为 H3 自动停止其他模型。
- 单副本 generic-proxy 路由使用专用 inference key；先验证鉴权、上传、长请求与返回文件。实际后端端口、路由 ID 和 key 都保留在私有部署记录。

可复用的 [backend 模板](../deploy/examples/h3-gpustack-backend.json) 与 [model 模板](../deploy/examples/h3-gpustack-model.json) 需要替换路径、worker、GPU 和允许访问的网关 IP；model 模板默认 0 副本。GPUStack 2.2.3 没有 video 分类，使用 `unknown` 和 generic proxy，不冒充 chat/image 接口。业务调用 `POST /v1/videos/sync`，上传 `input_reference`、`prompt`、`size`、`seconds` 与可选 `seed`；路径前缀由 GPUStack 路由提供。

用 [check_h3.py](../scripts/check_h3.py) 生成约 5 秒视频，检查 124 帧、24 FPS、32 kHz 双声道音频并用 ffmpeg 完整解码。默认 `--size 832x480`，768P 使用 `--size 1344x768`。key 仅从 stdin 读取。结果、耗时和散列存私有 output。若调用机没有 ffmpeg/ffprobe，可在同一固定 H3 镜像的无 GPU 临时容器中运行验收脚本，不向宿主安装 ML 依赖。

```bash
python scripts/check_h3.py --base-url http://<controller>:17880/model/proxy/<route-id> \
  --reference /path/to/reference.png --output-dir output/h3-acceptance/run-unique \
  --key-stdin < /private/h3-inference-key
```

若验收失败，停用本次新路由，将本次新 deployment 副本设为 0，撤销其专用 key；保留下载和证据。原有模型保持原配置。

## 已验证范围

2026-10-27，在单张 RTX PRO 6000 Blackwell Max-Q 上，使用相同参考图、prompt、seed=1234 和 36 层解码器，经 GPUStack 完成：

| 输出 | 网关端到端耗时 | H3 进程显存采样峰值 |
| --- | --- | --- |
| 832×480，约 5 秒 | 41.198 秒 | 12,916 MiB |
| 1344×768，约 5 秒 | 59.093 秒 | 19,890 MiB |

480P 是首次正式请求，768P 是后续请求；各一个样本，不是稳定吞吐或公平冷启动比较。显存每 2 秒采样，可能漏掉更短瞬时峰值。两段 MP4 均完整解码，音轨有非零信号、无数字削波；抽帧观察主体一致、运动连贯，没有明显破图，未对声音主观质量或复杂运动做系统评测。预览优先 480P，细节优先 768P；这组测量无需占用第二张 GPU。

网关无 key 返回 401，H3 key 访问其他模型返回 403，非白名单客户端直连后端返回 403。768P 生成期间，原有 LCA/Nemotron 的真实向量请求成功；原业务容器 ID 与启动时间保持不变。专用 key、路由 ID、主机路径、资源采样和样片保留在私有部署记录。
